**Known non-blocking issue (documented in SUMMARY):** Arrow zero-copy deserialization holds a reference to shared memory, causing `BufferError: cannot close exported pointers exist` at interpreter shutdown when Arrow objects are returned by `read()` in short-lived scripts. This is expected behavior (the Arrow object must outlive the shared memory mapping), produces only cleanup warnings at exit (not functional failures), and appears in neither test failures nor application crashes.

## Verification Details

### Plan 01 Artifacts (Arrow IPC Engine)

**`src/fastshare/_arrow_utils.py`** — Exists, 93 lines, fully substantive:
- `has_arrow()`: lazy import with `_arrow_available` cache
- `is_arrow_type()`: checks isinstance for all four Arrow types
- Constants: `ARROW_TYPE_TABLE=0x01`, `ARROW_TYPE_RECORD_BATCH=0x02`, `ARROW_TYPE_ARRAY=0x03`, `ARROW_TYPE_CHUNKED_ARRAY=0x04`, `ARROW_TYPE_PANDAS_DATAFRAME=0x05`
- `get_arrow_type_tag()`: returns correct constant per type
- `restore_arrow_type()`: converts IPC-deserialized Table back to original type
- `convert_pandas_to_arrow()`: converts pd.DataFrame to pa.Table with `was_pandas=True`

**`src/fastshare/_serializer.py`** — Updated, fully substantive:
- `FLAG_PICKLE = 0x00`, `FLAG_ARROW_IPC = 0x01` constants at module level
- `serialize_arrow_to_block(obj, type_tag)`: normalizes to Table, writes IPC stream to shared memory with memoryview cast `"B"` fix for buffer format compatibility
- `deserialize_arrow_from_block(handle)`: reads type tag, reads IPC data via `pa.py_buffer`, restores original type
- `deserialize_from_block()`: routes via `flags & FLAG_ARROW_IPC` check

**`src/fastshare/_estimator.py`** — Updated: Arrow fast path at lines 47-53, after NumPy fast path, before bytes-like fast path. Returns `int(obj.nbytes)` for Table/RecordBatch/Array/ChunkedArray.

**`pyproject.toml`** — Updated: `arrow = ["pyarrow>=2.0"]` in optional-dependencies, pyarrow in dev deps, "pyarrow" in keywords.
